    Operations

    How Snake, the inspector, and the live workspaces fit together

    Current operating model
    Operator guide

    Start with symptoms, then follow the owning signal

    Overview is the triage surface. Placement, callback timing, queue topology, cells, policy state, and debugging provide the evidence needed to explain a scheduling result.

    Open Overview Review scheduler controls Copy a debugging snapshot
    System map

    Inspector data flow

    Live scheduler state and tracepoint activity meet in one collector before reaching the browser.

    1. sched_switch activity enters the Placement probe.
    2. The Snake statistics and control socket supplies callback timing, policy, queue, and task state.
    3. Dashboard owns the joined state and rolling histories supplied by the collector to Overview and the detailed workspaces.
    4. Debugging packages the exact runtime context for escalation.
    Triage path

    Operator workflow

    Follow the symptom to its owning workspace; avoid changing policy before the signal is understood.

    1. Begin in Overview and identify whether the dominant signal is placement, callback cost, queueing, or cell ownership.
    2. Open the matching detailed workspace, then use Policy ladders to explain the decision path.
    3. Use Scheduler & policies only after the evidence is understood.
    4. Capture Debugging state before escalation or restart.
    Operating boundaries

    What changes live and what does not

    Fairness status

    FIFO is the default. VTIME and EEVDF remain experimental; EEVDF weighted shares are a known correctness blocker.

    Review fairness choices

    Dynamic changes

    Compatible policy ladders, callback sampling, timing captures, and task-cell annotations can change without reattaching Snake.

    Inspect live policy slots

    Restart boundaries

    Fairness, queue topology, cells, membership, CPU masks, weights, and DSQ layout are attachment-time state.

    Preview the restart command

    State lifetime

    Unapplied UI drafts and disclosure state do not survive refresh. Task annotations do not survive scheduler restart. Feedback drafts use tab session storage.

    Scale limits

    CPU IDs are bounded below 1,024. Queue mode supports 31 declared cells plus synthetic cell 0. Large-host inspector paths still need systematic scale evidence.

    Forward progress

    Direct borrowing helps newly runnable work, but already queued cross-cell backlog is not stolen. CPU hotplug and live owner changes are unsupported.

    Since the original review

    What changed

    Implemented mechanisms are separated from the evidence still needed.

    Managed lifecycle

    Direct-child reconciliation, exclusions, stable IDs, slot epochs, and a managed workload fixture are implemented. Immediate fork and move identity remains polling-bound.

    Resource allocation

    Effective-cpuset claims, deterministic ownership, cell-0 holdout, and infeasible-plan rejection are implemented. CPU hotplug remains unsupported.

    Dynamic control

    Elapsed-time demand samples, EWMA, thresholds, cooldowns, rebalances, and live telemetry are implemented. Long production-scale soak remains open.

    Banked publication

    Policy, managed topology, masks, descriptors, and routes stage together; old readers quiesce before reuse.

    Queue recovery

    Structural drain, in-place resize, orphan draining, and sibling stealing are implemented. Already queued work still cannot cross cell boundaries.

    Latency controls

    Live VTIME base-slice and pinned-waiter shrinking controls are implemented. Pinned-latency and fairness evidence remains open.

    Inspector and validation

    Managed capacity, rebalance, physical-core, host-tax, churn, resize, drain, and steal coverage landed. Sparse scale, browser, soak, and rollback evidence remains.

    Feature priorities

    Priority reflects dependency and risk reduction, not estimated effort.

    P0

    Observer isolation

    Ensure inspection and client failures cannot unwind the scheduler loop.

    P0

    Cross-cell queued-backlog contract

    Guarantee progress, reject unsafe demand, or alert and detach before watchdog exposure.

    P0

    CPU hotplug contract

    Handle online-mask changes transactionally or detect them and detach safely.

    P0

    Correct EEVDF weighted shares

    Fix or remove the exposed mode until nice-weight service ratios pass mandatory VM validation.

    P1

    Managed identity hardening

    Close or bound polling windows across fork, exec, cgroup moves, and slot reuse.

    P1

    Scale, soak, and rollback evidence

    Pass target-host scale curves, sustained soak, canary rollback, and restart-under-load campaigns.

    P1

    Browser and privileged VM CI

    Schedule managed VM coverage across supported kernels and run real-browser workflows in CI.

    P1

    Inspector large-host scaling

    Remove CPU-pair full-map scans, dense browser work, and duplicated polling.

    P2

    Typed Snake protocol

    Replace repeated loose JSON and error-string inference with shared DTOs and structured codes.

    P2

    Distance-ordered NUMA candidates

    Adapt LAVD's bounded topology ordering as an explicit policy operation.

    P3

    Pick-two remote balancing

    Consider only as an explicit approximate policy after a load signal exists.
